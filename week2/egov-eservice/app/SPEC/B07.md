# B07 · Workflow + routing + คิว/รับเรื่อง (409) + ตีกลับ ≤ 2 + อนุมัติ/ไม่อนุมัติ + เวลาแก้ไข 168 ชม. + แจ้งเตือน SLA

> อ่านเฉพาะไฟล์นี้ (ส่วนกลาง C1–C13 อยู่ท้ายไฟล์) · เขียนเฉพาะ `src/modules/workflow/`

## 3. API (ตรงตัว · ตรวจตามลำดับเลข · ทุกตัวทำใน `ctx.tx` แบบ sync)

ทุกตัว: ไม่ล็อกอิน → `401 UNAUTHENTICATED` · หาคำขอด้วย `case_no` ไม่พบ → `404 NOT_FOUND`

| Method · path | ใคร | request | สำเร็จ | ผิดพลาด (ตามลำดับ) |
|---|---|---|---|---|
| `POST /api/officer/cases/:caseNo/claim` | officer แผนกที่คำขออยู่ | – | `200 {"owner":"off.reg2"}` | ① role ≠ officer → `403 FORBIDDEN` ② 404 ③ `current_dept ≠ user.dept` → 403 ④ status ∉ {SUBMITTED, IN_REVIEW} → `409 INVALID_STATE` ⑤ `owner` มีค่า → `409 ALREADY_CLAIMED` (**B08 ข้ามข้อนี้**) ⑥ งานในมือ (IN_REVIEW ที่ owner = ฉัน) ≥ 10 → `409 WORKLOAD_LIMIT` |
| `POST /api/officer/cases/:caseNo/return` | ผู้ถือเรื่อง | `{"reason":"xxxxxxxxxx"}` | `200 {"status":"NEED_FIX","returnCount":1}` | ① role ≠ officer → 403 ② 404 ③ `owner ≠ me` → 403 ④ status ≠ IN_REVIEW → 409 INVALID_STATE ⑤ `return_count ≥ 2` → `409 RETURN_LIMIT` (**B12 ข้ามข้อนี้**) ⑥ `!reasonOk` → `400 REASON_TOO_SHORT` |
| `POST /api/officer/cases/:caseNo/forward` | ผู้ถือเรื่อง | `{"note":"…"}` (ไม่บังคับ) | SV-02 → `200 {"status":"PENDING_APPROVAL","step":null}` · SV-03 ขั้น 1 → `200 {"status":"IN_REVIEW","step":2}` · SV-03 ขั้น 2 → `200 {"status":"PENDING_APPROVAL","step":3}` | ① 403 ② 404 ③ `owner ≠ me` → 403 ④ status ≠ IN_REVIEW → 409 ⑤ SV-01 → `409 INVALID_STATE` |
| `POST /api/cases/:caseNo/approve` | SV-01: ผู้ถือ (officer) · SV-02/03: head | – | `200 {"status":"APPROVED"}` | ① role ∉ {officer, head} → 403 ② 404 ③ SV-01: ไม่ใช่ officer ผู้ถือ → 403 · SV-02/03: role ≠ head → 403 (**B07 ข้ามข้อนี้เฉพาะ SV-02/03**) ④ SV-01 status ≠ IN_REVIEW · SV-02/03 status ≠ PENDING_APPROVAL → `409 INVALID_STATE` |
| `POST /api/cases/:caseNo/reject` | เหมือน approve (ไม่มีบั๊ก) | `{"reason":"xxxxxxxxxx"}` | `200 {"status":"REJECTED","closedAt":"2026-12-01T09:00:00+07:00"}` | ①–④ เหมือน approve ⑤ `!reasonOk` → `400 REASON_TOO_SHORT` |

### 3.2 จุดฝัง BUG_MODE (ฝั่งเซิร์ฟเวอร์เท่านั้น)

```js
// B08 — claim: ข้ามการตรวจว่ามีผู้ถือแล้ว (คนที่ 2 ได้ 200 และเป็นผู้ถือแทน · Audit CLAIM เกิดซ้ำ)
if (row.owner && !ctx.bug('B08')) return ctx.fail(res, 'ALREADY_CLAIMED');
// B12 — return (API) และเงื่อนไข return-btn (pages.js): ตีกลับครั้งที่ 3 ได้
if (!ctx.bug('B12') && row.return_count >= 2) return ctx.fail(res, 'RETURN_LIMIT');
// B07 — approve SV-02/03: เจ้าหน้าที่อนุมัติเองได้ (ปุ่มยังซ่อน · reject ไม่มีบั๊ก)
if (row.service_id !== 'SV-01' && req.user.role !== 'head' && !ctx.bug('B07')) return ctx.fail(res, 'FORBIDDEN');
```

## 4. Hook ทุก request (hooks.js · ทำใน `ctx.tx` เดียว · ลำดับ 4.1 แล้ว 4.2)

### 4.1 ยกเลิกอัตโนมัติเมื่อเลย 168 ชม. (A-46)
`SELECT id, fix_deadline FROM cases WHERE status='NEED_FIX' AND fix_deadline IS NOT NULL` → แถวที่ `now.getTime() >= Date.parse(fix_deadline)` → `UPDATE status='CANCELLED', cancelled_at=fix_deadline, cancel_reason='FIX_EXPIRED', updated_at=nowIso` → `ctx.caseEvent(id, 'AUTO_CANCEL', 'ระบบยกเลิกอัตโนมัติ (เลยเวลาแก้ไข 168 ชั่วโมง)', fix_deadline)` (เวลาในไทม์ไลน์ = ตีกลับ + 168 ชม.)

### 4.2 แจ้งเตือน SLA (A-30 A-31 · 1 ครั้งต่อระดับต่อคำขอต่อคน)

```text
now = ctx.clock.now() · hol = ctx.holidays()
staff = SELECT username, role, dept FROM users WHERE kind='staff'
heads = staff.filter(role==='head') · officersOf(d) = staff.filter(role==='officer' && dept===d)
for c in SELECT id, case_no, status, current_dept, owner, issuer, due_at FROM cases
         WHERE status IN ('SUBMITTED','IN_REVIEW','PENDING_APPROVAL','APPROVED') AND due_at IS NOT NULL:
   level = ctx.rules.slaLevel(c, now, hol)            ← ประเมินเฉพาะระดับปัจจุบัน (ไม่ย้อนแจ้ง near ถ้ากระโดดไป overdue)
   if level ∉ {near, overdue} continue
   to = PENDING_APPROVAL → heads
        APPROVED         → [c.issuer] (issuer NULL → officersOf('registry'))
        owner มีค่า       → [c.owner]
        อื่น (ไม่มีผู้ถือ)  → officersOf(c.current_dept)
   if level === 'overdue' → to += heads (ตัดซ้ำ)
   for u in to: INSERT OR IGNORE INTO notifications(username, case_id, case_no, level, text, created_at)
                VALUES (u, c.id, c.case_no, level, 'คำขอ ' + c.case_no + ' ' + (level==='near' ? 'ใกล้ครบกำหนด' : 'เกินกำหนด'), nowIso)
```

### C6. ผู้ใช้ใน request และ session

- cookie ชื่อ `sid` (hex 32 ตัว) `HttpOnly; Path=/; SameSite=Lax` · session เก็บใน `Map` ในหน่วยความจำ (**ไม่เก็บลง DB** เพื่อไม่ให้เลขบัตรของผู้ลงทะเบียนค้างในไฟล์) · `POST /api/test/reset` และการ restart ล้างทั้งหมด
- `req.user` = `null` หรือ `{ id, kind: 'citizen'|'staff', username: string|null, name, role, dept: 'registry'|'works'|null }` (ค่า role/dept เป็น snapshot ตอนล็อกอิน · admin เปลี่ยนบทบาทแล้วมีผลเมื่อล็อกอินใหม่)
- `req.pending` = `null` หรือ `{ userId: number|null, idNo, idHash, name }` (ผ่าน OTP แล้วแต่ยังไม่ลงทะเบียน · ใช้ได้เฉพาะ `/register` และ `POST /api/auth/register` · ถือว่า "ยังไม่ล็อกอิน" สำหรับทุกเส้นทางอื่น)
- บทบาท: `citizen` `officer` `head` `executive` `auditor` `admin` · แผนก: `registry` `works` (เฉพาะ officer)

### C7. กติกาเวลา (Asia/Bangkok +07:00)

1. เวลาทุกค่าใน DB และใน JSON เป็นสตริง `YYYY-MM-DDTHH:mm:ss+07:00` (ไม่มี ms · ไม่มี `Z`) → เปรียบเทียบด้วยสตริงได้ แต่ **ให้เปรียบเทียบด้วย `Date.parse()`** เพื่อความชัวร์
2. วันที่ล้วน (วันหยุด, `valid_until`, ตัวกรอง Audit) เป็น `YYYY-MM-DD` ค.ศ. ตามปฏิทินไทย
3. แปลงเวลาไทย: ไทยไม่มี DST → `new Date(ms + 7*3600*1000)` แล้วใช้ `getUTC*()` (ฟังก์ชันพร้อมใช้อยู่ใน `ctx.rules`) · ห้ามพึ่ง timezone ของเครื่อง
4. อ่าน "ตอนนี้" จาก `ctx.clock.now()` / `ctx.clock.nowIso()` เท่านั้น
5. บนจอ: `4 ธ.ค. 2569 16:30` (วันไม่เติม 0 · ชั่วโมง/นาที 2 หลัก · พ.ศ. = ค.ศ. + 543) · วันที่ล้วน `28 ก.พ. 2570` · เงิน `฿1,010` · ทุก element วันเวลามี `data-iso` (วันเวลา = ISO เต็ม · วันที่ล้วน = `YYYY-MM-DD`)

### C11. กติกาหน้าเว็บ (ทุกบล็อกที่ทำหน้า)

1. ใช้ `ctx.render(req, res, {title, body, script})` เสมอ · `body` ต้อง escape ค่าจาก DB ด้วย `ctx.esc`
2. **ข้อความใน element ที่มี `data-testid` = ค่าตรงตัวเท่านั้น** (ป้ายกำกับเช่น "ค่าธรรมเนียม:" อยู่นอก element) เช่น `<p>ค่าธรรมเนียม <strong data-testid="fee-total">฿1,010</strong></p>`
3. element ที่ "แสดงเมื่อ…/ไม่ render เมื่อ…" → **ไม่อยู่ใน DOM** เมื่อไม่เข้าเงื่อนไข (ห้ามซ่อนด้วย `hidden`/CSS) · ปุ่ม "ใช้ไม่ได้" → อยู่ใน DOM พร้อม `disabled`
4. รายการซ้ำใช้ testid ซ้ำได้ แต่ **ห้ามใช้ `id` ซ้ำ** · ช่องกรอกทุกช่องมี `<label for>` หรือ `aria-label` · ปุ่มทุกปุ่มมีข้อความ
5. ตารางห่อด้วย `<div class="table-wrap" tabindex="0" role="region" aria-label="…">` · หัวตาราง `<th scope="col">` มีข้อความทุกช่อง
6. ปุ่มที่เรียก API: ใช้ `App.api()` → สำเร็จ = `location.reload()` (หรืออัปเดตหน้าตามที่สเปกระบุ) · ไม่สำเร็จ = `App.showError(data.message)` (เว้นแต่สเปกระบุ testid error เฉพาะช่อง) · ห้าม `alert()`/`confirm()` ของเบราว์เซอร์
7. สถานะ/ระดับใช้ `ctx.views.statusBadge` / `levelBadge` เสมอ (มีข้อความ + สี)
8. ห้ามใส่เลขบัตร 13 หลัก/เบอร์โทรเต็มใน HTML ของจอเจ้าหน้าที่/ผู้บริหาร (ยกเว้นหลัง unmask ที่ JS ใส่เอง)

ตัวช่วยฝั่ง client ที่ layout (B01) ใส่ให้ทุกหน้า (`window.App`):

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `App.api(method, url, body?)` | `fetch` แบบ same-origin · `body` เป็น object → JSON · เป็น `FormData` → multipart · คืน `Promise<{ok, status, data}>` (`data` = JSON ที่ parse แล้ว หรือ `null`) |
| `App.showError(msg)` | แทนเนื้อหา `#flash` ด้วย `<div data-testid="action-error" role="alert" class="alert-error">msg</div>` |
| `App.showSuccess(msg)` | แทนเนื้อหา `#flash` ด้วย `<div data-testid="action-success" role="status" class="alert-success">msg</div>` |

| `App.esc(s)` · `App.baht(n)` · `App.fmtId(id13)` · `App.thaiDateTime(iso)` · `App.thaiDate('YYYY-MM-DD')` | escape · `฿1,010` · `3-1006-00987-65-9` · `1 ธ.ค. 2569 09:15` (ตัดจากสตริง ISO +07:00 ตรง ๆ) · `28 ก.พ. 2570` |
