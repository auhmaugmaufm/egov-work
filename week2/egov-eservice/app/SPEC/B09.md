## 3. API (ตรงตัว)

| Method · path | สิทธิ์ | สำเร็จ | ผิดพลาด (ตามลำดับ) |
|---|---|---|---|
| `GET /api/dashboard?period=2026-11&service=ALL` | executive | `200 {"received":26,"closed":7,"onTime":6,"ontimePct":85.7,"backlog":21,"overdue":1,"workload":[{"username":"off.reg1","count":3},{"username":"off.reg2","count":9},{"username":"off.works1","count":0}]}` · ปิดงาน 0 → `"ontimePct":null` | ① 401 ② ไม่ใช่ executive → `403 FORBIDDEN` ③ period ไม่ตรง `/^\d{4}(-(0[1-9]\|1[0-2]))?$/` → `400 INVALID_PERIOD` ④ service ∉ {ALL, SV-01, SV-02, SV-03} → `400 INVALID_SERVICE` |
| `GET /api/dashboard/export?format=xlsx\|pdf&period=…&service=…` | executive | ไฟล์ (ข้อ 3.2) + Audit `EXPORT` | ①–④ เหมือนข้างบน ⑤ format อื่น → `400 BAD_REQUEST` |

ไม่ส่ง period/service → ค่าเริ่มต้นเหมือนหน้า

### 3.1 `computeKpi(ctx, period, service)` (จุด B10)

```text
now = ctx.clock.now()
match(iso) = iso !== null && iso.startsWith(period)        ← ISO เก็บเป็นเวลาไทย จึงใช้ prefix 'YYYY-MM' หรือ 'YYYY' ได้ตรง
svcOk(r)   = service === 'ALL' || r.service_id === service
rows = SELECT service_id, status, paid_at, due_at, closed_at, owner FROM cases WHERE case_no IS NOT NULL
received  = rows.filter(r => svcOk(r) && match(r.paid_at)).length                 ← รวม CANCELLED ที่เคยชำระ
closedRows= rows.filter(r => svcOk(r) && CLOSED_STATUSES.includes(r.status) && match(r.closed_at))   ← COMPLETED + REJECTED
closed    = closedRows.length
onTime    = closedRows.filter(r => ctx.rules.isOnTime(r.closed_at, r.due_at)).length   ← closed_at ≤ due_at (รวม 16:30:00)
backlog   = rows.filter(r => svcOk(r) && BACKLOG_STATUSES.includes(r.status)).length    ← ณ ตอนนี้ ไม่ขึ้นกับ period
overdue   = rows.filter(r => svcOk(r) && BACKLOG_STATUSES.includes(r.status) && r.status !== 'NEED_FIX'
                         && now.getTime() > Date.parse(r.due_at)).length
workload  = SELECT username FROM users WHERE role='officer' ORDER BY username → count IN_REVIEW ที่ owner = username (ไม่ขึ้นกับตัวกรองใด)
```
```js
const denom = ctx.bug('B10') ? received : closed;     // B10: หารด้วย "รับเรื่อง" แทน "ปิดงาน"
const ontimePct = ctx.rules.pct1(onTime, denom);      // denom 0 → null · ปัดครึ่งขึ้น 1 ตำแหน่ง
```
รายปี (`period='2026'`) ใช้สูตรเดียวกัน = รวมทุกเดือนแล้วคิด % จากยอดรวม (ไม่เฉลี่ย % รายเดือน)

### 3.2 ไฟล์ส่งออก (ค่า = ข้อความเดียวกับบนจอทุกช่อง)

ค่าที่แสดง: `received` `closed` `backlog` `overdue` เป็น `String(n)` · ทันกำหนด = `formatPct(ontimePct)` (`85.7%` หรือ `–`)

| format | เนื้อหา | headers |
|---|---|---|
| xlsx | exceljs: ชีตแรกชื่อ `Dashboard` · แถว 1 `ตัวชี้วัด` \| `ค่า` · แถว 2–6 คอลัมน์ A `รับเรื่อง` `ปิดงาน` `ทันกำหนด %` `งานคงค้าง` `เกินกำหนดคงค้าง` · คอลัมน์ B ค่าเป็น **ข้อความ** (เช่น `'26'` `'85.7%'` `'–'`) · ไม่มีแถวอื่น | `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` · `Content-Disposition: attachment; filename="dashboard-<period>-<service>.xlsx"` |
| pdf | `ctx.pdf.makeSimplePdf([...])` บรรทัด: `e-Service dashboard report (simulated municipality)` · `period=<period> service=<service>` · `kpi received=26 closed=7 ontime=85.7% backlog=21 overdue=1` (ปิดงาน 0 → `ontime=-` ใช้ `-` ASCII) | `Content-Type: application/pdf` · `Content-Disposition: attachment; filename="dashboard-<period>-<service>.pdf"` |

หลังสร้างไฟล์เสร็จ: `ctx.audit(req.user, {event:'EXPORT', detail: format + ' ' + period + ' ' + service})` เช่น `xlsx 2026-11 ALL` · ไม่มีชื่อ/เลขบัตร/เบอร์ในไฟล์

### C3. interface ของ module


- ทุก handler ที่ "อ่านแล้วเขียน" ต้องทำ **แบบ sync ใน `ctx.tx(() => …)` ไม่มี `await` คั่น** (Node thread เดียว + better-sqlite3 sync = คำขอพร้อมกันถูกเรียงคิวเอง → การรับเรื่องพร้อมกัน/ชำระพร้อมกันได้ผลถูก)
- ห้ามเก็บ prepared statement ไว้ระดับ module ให้ `ctx.db.prepare(sql)` ในฟังก์ชัน

### C6. ผู้ใช้ใน request และ session

- cookie ชื่อ `sid` (hex 32 ตัว) `HttpOnly; Path=/; SameSite=Lax` · session เก็บใน `Map` ในหน่วยความจำ (**ไม่เก็บลง DB** เพื่อไม่ให้เลขบัตรของผู้ลงทะเบียนค้างในไฟล์) · `POST /api/test/reset` และการ restart ล้างทั้งหมด
- `req.user` = `null` หรือ `{ id, kind: 'citizen'|'staff', username: string|null, name, role, dept: 'registry'|'works'|null }` (ค่า role/dept เป็น snapshot ตอนล็อกอิน · admin เปลี่ยนบทบาทแล้วมีผลเมื่อล็อกอินใหม่)

### C7. กติกาเวลา (Asia/Bangkok +07:00)

1. เวลาทุกค่าใน DB และใน JSON เป็นสตริง `YYYY-MM-DDTHH:mm:ss+07:00` (ไม่มี ms · ไม่มี `Z`) → เปรียบเทียบด้วยสตริงได้ แต่ **ให้เปรียบเทียบด้วย `Date.parse()`** เพื่อความชัวร์
2. วันที่ล้วน (วันหยุด, `valid_until`, ตัวกรอง Audit) เป็น `YYYY-MM-DD` ค.ศ. ตามปฏิทินไทย
3. แปลงเวลาไทย: ไทยไม่มี DST → `new Date(ms + 7*3600*1000)` แล้วใช้ `getUTC*()` (ฟังก์ชันพร้อมใช้อยู่ใน `ctx.rules`) · ห้ามพึ่ง timezone ของเครื่อง
4. อ่าน "ตอนนี้" จาก `ctx.clock.now()` / `ctx.clock.nowIso()` เท่านั้น
5. บนจอ: `4 ธ.ค. 2569 16:30` (วันไม่เติม 0 · ชั่วโมง/นาที 2 หลัก · พ.ศ. = ค.ศ. + 543) · วันที่ล้วน `28 ก.พ. 2570` · เงิน `฿1,010` · ทุก element วันเวลามี `data-iso` (วันเวลา = ISO เต็ม · วันที่ล้วน = `YYYY-MM-DD`)

### C11. กติกาหน้าเว็บ (ทุกบล็อกที่ทำหน้า)

1. ใช้ `ctx.render(req, res, {title, body, script})` เสมอ · `body` ต้อง escape ค่าจาก DB ด้วย `ctx.esc`
2. **ข้อความใน element ที่มี `data-testid` = ค่าตรงตัวเท่านั้น** (ป้ายกำกับเช่น "ค่าธรรมเนียม:" อยู่นอก element) เช่น `<p>ค่าธรรมเนียม <strong data-testid="fee-total">฿1,010</strong></p>`
3. element ที่ "แสดงเมื่อ…/ไม่ render เมื่อ…" → **ไม่อยู่ใน DOM** เมื่อไม่เข้าเงื่อนไข (ห้ามซ่อนด้วย `hidden`/CSS) · ปุ่ม "ใช้ไม่ได้" → อยู่ใน DOM พร้อม `disabled`
4. รายการซ้ำใช้ testid ซ้ำได้ แต่ **ห้ามใช้ `id` ซ้ำ** · ช่องกรอกทุกช่องมี `<label for>` หรือ `aria-label` · ปุ่มทุกปุ่มมีข้อความ
5. ตารางห่อด้วย `<div class="table-wrap" tabindex="0" role="region" aria-label="…">` · หัวตาราง `<th scope="col">` มีข้อความทุกช่อง
6. ปุ่มที่เรียก API: ใช้ `App.api()` → สำเร็จ = `location.reload()` (หรืออัปเดตหน้าตามที่สเปกระบุ) · ไม่สำเร็จ = `App.showError(data.message)` (เว้นแต่สเปกระบุ testid error เฉพาะช่อง) · ห้าม `alert()`/`confirm()` ของเบราว์เซอร์
7. สถานะ/ระดับใช้ `ctx.views.statusBadge` / `levelBadge` เสมอ (มีข้อความ + สี)
8. ห้ามใส่เลขบัตร 13 หลัก/เบอร์โทรเต็มใน HTML ของจอเจ้าหน้าที่/ผู้บริหาร (ยกเว้นหลัง unmask ที่ JS ใส่เอง)

ตัวช่วยฝั่ง client ที่ layout (B01) ใส่ให้ทุกหน้า (`window.App`):

```sql
  valid_until TEXT NOT NULL,                   -- 'YYYY-MM-DD'
  signer      TEXT NOT NULL,                   -- ชื่อแสดงของผู้อนุมัติ เช่น 'หัวหน้าฝ่าย'
  signature   TEXT NOT NULL,                   -- hmacDoc([doc_no, case_no, applicant, service_id, issued_at, valid_until, signer])
  issued_by   TEXT
);
CREATE TABLE IF NOT EXISTS notifications (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  username   TEXT NOT NULL,
  case_id    INTEGER NOT NULL,
  case_no    TEXT NOT NULL,

CREATE TABLE IF NOT EXISTS case_events (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  case_id INTEGER NOT NULL,
  at      TEXT NOT NULL,
  type    TEXT NOT NULL,                       -- PAID CLAIM RETURN RESUBMIT FORWARD APPROVE REJECT ISSUE CANCEL AUTO_CANCEL
  text    TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS otp_attempts (
  id_hash      TEXT PRIMARY KEY,               -- ctx.crypto.hashId(idNo)
  fail_count   INTEGER NOT NULL DEFAULT 0,
  locked_until TEXT
);
```
