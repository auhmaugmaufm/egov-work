### 3.1 แถวของ `GET /api/officer/queue` (จุด B09)

ข้อมูลเหมือนหน้าคิวของ B07: `SELECT c.*, u.name AS applicant_name, u.id_enc FROM cases c JOIN users u ON u.id = c.applicant_id WHERE c.case_no IS NOT NULL` → `ctx.rules.selectQueue(rows, req.user, filter)` (filter ไม่รู้จัก = all)

```json
{"caseNo":"EG-2569-000025","serviceId":"SV-01","applicantName":"สมหญิง รักไทย","idMasked":"X-XXXX-XXXXX-65-9",
 "status":"IN_REVIEW","step":null,"owner":"off.reg2","dueAt":"2026-12-03T16:30:00+07:00","slaLevel":"normal"}
```
```js
const idNo = ctx.crypto.decrypt(r.id_enc);
const item = { caseNo: r.case_no, serviceId: r.service_id, applicantName: r.applicant_name, idMasked: ctx.rules.maskId(idNo),
  status: r.status, step: r.step, owner: r.owner, dueAt: r.due_at, slaLevel: ctx.rules.slaLevel(r, now, hol) };
if (ctx.bug('B09')) item.idNo = idNo;          // B09: API ส่งเลขบัตรเต็ม (จอยังปิดบัง)
```
ปกติ: response ต้องไม่มีคีย์ `idNo` และไม่มีสตริงตรง `\d{13}` หรือ `\d-\d{4}-\d{5}-\d{2}-\d`

### 3.4 `verifyDoc(code)` (ใช้ทั้งหน้าและ API · ลำดับตรวจ A-43)

```text
doc = documents WHERE verify_code = code            → ไม่มี → NOT_FOUND (404)
sig = hmacDoc([doc_no, case_no, applicant, service_id, issued_at, valid_until, signer])
sig !== doc.signature                                → TAMPERED  (ตรวจก่อนหมดอายุ: ทั้งแก้และหมดอายุ = TAMPERED)
ctx.rules.isDocExpired(valid_until, ctx.clock.now()) → EXPIRED
อื่น                                                 → VALID
```
JSON VALID/EXPIRED: `docNo` · `applicantMasked = rules.maskName(applicant)` · `serviceId` · `issuedAt` · `validUntil` (`YYYY-MM-DD`) · `signer`

### 3.5 สิทธิ์ PDF / ไฟล์ของ citizen
citizen: `cases.applicant_id === req.user.id` (ผ่าน `documents.case_id`) ไม่งั้น 404 · officer/head: ได้ทุกใบ · executive/auditor/admin: 404 (CONTRACT "คนอื่น → 404")

### 3.6 ตัวกรอง Audit (API และหน้าใช้ร่วม)

| param | ทำอะไร |
|---|---|
| `actor` | trim · ไม่ว่าง → `username = ?` (ตรงตัว) |
| `event` | ไม่ว่าง → `event = ?` |
| `from` | ตรง `/^\d{4}-\d{2}-\d{2}$/` → `time >= from + 'T00:00:00+07:00'` · ผิดรูปแบบ → `400 INVALID_DATE` |
| `to` | → `time <= to + 'T23:59:59+07:00'` (รวมทั้งวันตามเวลาไทย) |
| เรียง | `time DESC, id DESC` |

### 3.7 CSV
`Content-Type: text/csv; charset=utf-8` · `Content-Disposition: attachment; filename="audit.csv"` · UTF-8 ไม่มี BOM · บรรทัดแรก `time,username,role,event,caseNo,fromStatus,toStatus,detail` · ต่อด้วยแถวตามตัวกรอง/ลำดับเดียวกับ API · ค่า null = ว่าง · ฟิลด์ที่มี `,` `"` หรือขึ้นบรรทัด → ครอบ `"…"` และ `"` → `""` · ทุกบรรทัด (รวมบรรทัดสุดท้าย) ลงท้าย `\n` · **สร้าง CSV ให้เสร็จก่อน** แล้วจึง `ctx.audit(req.user, {event:'EXPORT', detail:'audit-csv'})` (CSV จึงไม่มีแถว EXPORT ของตัวเอง)

### C3. interface ของ module

```js
// src/modules/<ชื่อ>/routes.js
module.exports = function register(app, ctx) {
  app.get('/api/xxx', ctx.requireApi('officer', 'head'), (req, res) => { /* ... */ });
};
```

- `src/app.js` (B01) อ่านทุกโฟลเดอร์ใน `src/modules/` เรียงตามตัวอักษร แล้วเรียก `require('./modules/<ชื่อ>/routes.js')(app, ctx)` ครั้งเดียวตอนเริ่ม · โฟลเดอร์ที่ไม่มี `routes.js` ถูกข้าม
- ภายใน module `require('./pages')` ได้ · **ห้าม require ไฟล์ของ module อื่น** · ใช้ของกลางผ่าน `ctx` เท่านั้น
- ทุก handler ที่ "อ่านแล้วเขียน" ต้องทำ **แบบ sync ใน `ctx.tx(() => …)` ไม่มี `await` คั่น** (Node thread เดียว + better-sqlite3 sync = คำขอพร้อมกันถูกเรียงคิวเอง → การรับเรื่องพร้อมกัน/ชำระพร้อมกันได้ผลถูก)
- ห้ามเก็บ prepared statement ไว้ระดับ module ให้ `ctx.db.prepare(sql)` ในฟังก์ชัน

### C7. กติกาเวลา (Asia/Bangkok +07:00)

1. เวลาทุกค่าใน DB และใน JSON เป็นสตริง `YYYY-MM-DDTHH:mm:ss+07:00` (ไม่มี ms · ไม่มี `Z`) → เปรียบเทียบด้วยสตริงได้ แต่ **ให้เปรียบเทียบด้วย `Date.parse()`** เพื่อความชัวร์
2. วันที่ล้วน (วันหยุด, `valid_until`, ตัวกรอง Audit) เป็น `YYYY-MM-DD` ค.ศ. ตามปฏิทินไทย
3. แปลงเวลาไทย: ไทยไม่มี DST → `new Date(ms + 7*3600*1000)` แล้วใช้ `getUTC*()` (ฟังก์ชันพร้อมใช้อยู่ใน `ctx.rules`) · ห้ามพึ่ง timezone ของเครื่อง
4. อ่าน "ตอนนี้" จาก `ctx.clock.now()` / `ctx.clock.nowIso()` เท่านั้น
5. บนจอ: `4 ธ.ค. 2569 16:30` (วันไม่เติม 0 · ชั่วโมง/นาที 2 หลัก · พ.ศ. = ค.ศ. + 543) · วันที่ล้วน `28 ก.พ. 2570` · เงิน `฿1,010` · ทุก element วันเวลามี `data-iso` (วันเวลา = ISO เต็ม · วันที่ล้วน = `YYYY-MM-DD`)

1. ใช้ `ctx.render(req, res, {title, body, script})` เสมอ · `body` ต้อง escape ค่าจาก DB ด้วย `ctx.esc`
2. **ข้อความใน element ที่มี `data-testid` = ค่าตรงตัวเท่านั้น** (ป้ายกำกับเช่น "ค่าธรรมเนียม:" อยู่นอก element) เช่น `<p>ค่าธรรมเนียม <strong data-testid="fee-total">฿1,010</strong></p>`
3. element ที่ "แสดงเมื่อ…/ไม่ render เมื่อ…" → **ไม่อยู่ใน DOM** เมื่อไม่เข้าเงื่อนไข (ห้ามซ่อนด้วย `hidden`/CSS) · ปุ่ม "ใช้ไม่ได้" → อยู่ใน DOM พร้อม `disabled`
4. รายการซ้ำใช้ testid ซ้ำได้ แต่ **ห้ามใช้ `id` ซ้ำ** · ช่องกรอกทุกช่องมี `<label for>` หรือ `aria-label` · ปุ่มทุกปุ่มมีข้อความ
5. ตารางห่อด้วย `<div class="table-wrap" tabindex="0" role="region" aria-label="…">` · หัวตาราง `<th scope="col">` มีข้อความทุกช่อง
6. ปุ่มที่เรียก API: ใช้ `App.api()` → สำเร็จ = `location.reload()` (หรืออัปเดตหน้าตามที่สเปกระบุ) · ไม่สำเร็จ = `App.showError(data.message)` (เว้นแต่สเปกระบุ testid error เฉพาะช่อง) · ห้าม `alert()`/`confirm()` ของเบราว์เซอร์
7. สถานะ/ระดับใช้ `ctx.views.statusBadge` / `levelBadge` เสมอ (มีข้อความ + สี)
8. ห้ามใส่เลขบัตร 13 หลัก/เบอร์โทรเต็มใน HTML ของจอเจ้าหน้าที่/ผู้บริหาร (ยกเว้นหลัง unmask ที่ JS ใส่เอง)

ตัวช่วยฝั่ง client ที่ layout (B01) ใส่ให้ทุกหน้า (`window.App`):

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `App.api(method, url, body?)` | `fetch` แบบ same-origin · `body` เป็น object → JSON · เป็น `FormData` → multipart · คืน `Promise<{ok, status, data}>` (`data` = JSON ที่ parse แล้ว หรือ `null`) |
| `App.showError(msg)` | แทนเนื้อหา `#flash` ด้วย `<div data-testid="action-error" role="alert" class="alert-error">msg</div>` |
| `App.showSuccess(msg)` | แทนเนื้อหา `#flash` ด้วย `<div data-testid="action-success" role="status" class="alert-success">msg</div>` |
| `App.clearFlash()` | ล้าง `#flash` |
| `App.esc(s)` · `App.baht(n)` · `App.fmtId(id13)` · `App.thaiDateTime(iso)` · `App.thaiDate('YYYY-MM-DD')` | escape · `฿1,010` · `3-1006-00987-65-9` · `1 ธ.ค. 2569 09:15` (ตัดจากสตริง ISO +07:00 ตรง ๆ) · `28 ก.พ. 2570` |

คลาส CSS ที่ layout มีให้: `btn` `btn-secondary` `btn-danger` `badge` `st-<STATUS>` `lv-<level>` `table-wrap` `card` `form-row` `alert-error` `alert-success` `muted` `grid-kpi` `toolbar` `dialog` `visually-hidden`
