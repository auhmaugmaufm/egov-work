## 3. API (ทุกตัว `ctx.requireApi('admin')` → ไม่ล็อกอิน 401 · บทบาทอื่น 403)

| Method · path | request | สำเร็จ | ผิดพลาด (ตามลำดับ) |
|---|---|---|---|
| `GET /api/admin/services` | – | `200 {"items":[{"id":"SV-01","fee":20,"feePerSqm":null,"sla":3},{"id":"SV-02","fee":500,"feePerSqm":null,"sla":10},{"id":"SV-03","fee":1000,"feePerSqm":10,"sla":15}]}` | – |
| `PUT /api/admin/services/:id` | SV-01/02 `{"fee":25,"sla":3}` · SV-03 `{"feeBase":1000,"feePerSqm":10,"sla":15}` (SV-03 รับ `fee` เป็นชื่อแทน `feeBase` ได้) · ฟิลด์ไม่ส่ง = ไม่แก้ | `200 {"id":"SV-01","fee":25,"feePerSqm":null,"sla":3}` | ① `:id` ไม่มี → `404 NOT_FOUND` ② ไม่มีฟิลด์ใดเลย → `400 BAD_REQUEST` ③ ค่าธรรมเนียมทุกฟิลด์ที่ส่ง (`fee`/`feeBase`/`feePerSqm`) ต้อง `Number.isInteger(v) && 0 <= v <= 100000` → `400 INVALID_FEE` ④ `sla` ที่ส่งต้อง `Number.isInteger(v) && 1 <= v <= 60` → `400 INVALID_SLA` · ผิดข้อใดข้อหนึ่ง = **ไม่แก้อะไรเลย** |
| `GET /api/admin/holidays` | – | `200 {"items":[{"date":"2026-12-07","name":"ชดเชยวันหยุดทดสอบ (สมมติ)"}, …]}` | – |
| `POST /api/admin/holidays` | `{"date":"2026-12-02","name":"วันหยุดทดสอบ"}` | `201 {"date":"2026-12-02","name":"วันหยุดทดสอบ"}` (ชื่อว่าง → `วันหยุด`) · วันเสาร์/อาทิตย์เพิ่มได้ | ① `date` ไม่ตรง `/^\d{4}-\d{2}-\d{2}$/` หรือไม่ใช่วันที่จริง → `400 INVALID_DATE` ② มีอยู่แล้ว → `409 DUPLICATE_HOLIDAY` |
| `DELETE /api/admin/holidays/:date` | – | `200 {"ok":true}` | ไม่มี → `404 NOT_FOUND` |
| `GET /api/admin/users` | – | `200 {"items":[{"username":"off.reg1","name":"เจ้าหน้าที่ทะเบียน 1","role":"officer","dept":"registry"}, …]}` (staff 7 คน) | – |
| `PUT /api/admin/users/:username` | `{"role":"executive","dept":""}` | `200 {"username":"audit1","role":"executive","dept":null}` | ① ไม่มี staff ชื่อนี้ → 404 ② `:username === req.user.username` → `409 SELF_ROLE_CHANGE` (ตรวจก่อนค่าอื่น) ③ role ∉ {officer, head, executive, auditor, admin} → `400 INVALID_ROLE` (ไม่ให้ตั้ง citizen) ④ role = officer และ dept ∉ {registry, works} → `400 INVALID_DEPT` · role อื่น → dept บังคับเป็น NULL |

### 3.1 บันทึกและ Audit (ใน `ctx.tx`)

| การแก้ | UPDATE | Audit `ADMIN_CHANGE` detail (เฉพาะที่ค่าเปลี่ยนจริง) |
|---|---|---|
| ค่าธรรมเนียม SV-01/02 | `services.fee` | `SV-01 fee 20 → 25` |

| ลบวันหยุด | DELETE | `holiday delete 2026-12-02` |
| บทบาท | `users.role` | `exec1 role executive → auditor` |
| แผนก | `users.dept` | `off.reg1 dept registry → works` (NULL แสดงเป็น `-`) |

### C3. interface ของ module


- ทุก handler ที่ "อ่านแล้วเขียน" ต้องทำ **แบบ sync ใน `ctx.tx(() => …)` ไม่มี `await` คั่น** (Node thread เดียว + better-sqlite3 sync = คำขอพร้อมกันถูกเรียงคิวเอง → การรับเรื่องพร้อมกัน/ชำระพร้อมกันได้ผลถูก)
- ห้ามเก็บ prepared statement ไว้ระดับ module ให้ `ctx.db.prepare(sql)` ในฟังก์ชัน

### C6. ผู้ใช้ใน request และ session

- cookie ชื่อ `sid` (hex 32 ตัว) `HttpOnly; Path=/; SameSite=Lax` · session เก็บใน `Map` ในหน่วยความจำ (**ไม่เก็บลง DB** เพื่อไม่ให้เลขบัตรของผู้ลงทะเบียนค้างในไฟล์) · `POST /api/test/reset` และการ restart ล้างทั้งหมด
- `req.user` = `null` หรือ `{ id, kind: 'citizen'|'staff', username: string|null, name, role, dept: 'registry'|'works'|null }` (ค่า role/dept เป็น snapshot ตอนล็อกอิน · admin เปลี่ยนบทบาทแล้วมีผลเมื่อล็อกอินใหม่)
- `req.pending` = `null` หรือ `{ userId: number|null, idNo, idHash, name }` (ผ่าน OTP แล้วแต่ยังไม่ลงทะเบียน · ใช้ได้เฉพาะ `/register` และ `POST /api/auth/register` · ถือว่า "ยังไม่ล็อกอิน" สำหรับทุกเส้นทางอื่น)
- บทบาท: `citizen` `officer` `head` `executive` `auditor` `admin` · แผนก: `registry` `works` (เฉพาะ officer)

### C7. กติกาเวลา (Asia/Bangkok +07:00)

1. เวลาทุกค่าใน DB และใน JSON เป็นสตริง `YYYY-MM-DDTHH:mm:ss+07:00` (ไม่มี ms · ไม่มี `Z`) → เปรียบเทียบด้วยสตริงได้ แต่ **ให้เปรียบเทียบด้วย `Date.parse()`** เพื่อความชัวร์
2. วันที่ล้วน (วันหยุด, `valid_until`, ตัวกรอง Audit) เป็น `YYYY-MM-DD` ค.ศ. ตามปฏิทินไทย
3. แปลงเวลาไทย: ไทยไม่มี DST → `new Date(ms + 7*3600*1000)` แล้วใช้ `getUTC*()` (ฟังก์ชันพร้อมใช้อยู่ใน `ctx.rules`) · ห้ามพึ่ง timezone ของเครื่อง
4. อ่าน "ตอนนี้" จาก `ctx.clock.now()` / `ctx.clock.nowIso()` เท่านั้น
5. บนจอ: `4 ธ.ค. 2569 16:30` (วันไม่เติม 0 · ชั่วโมง/นาที 2 หลัก · พ.ศ. = ค.ศ. + 543) · วันที่ล้วน `28 ก.พ. 2570` · เงิน `฿1,010` · ทุก element วันเวลามี `data-iso` (วันเวลา = ISO เต็ม · วันที่ล้วน = `YYYY-MM-DD`)

### C11. กติกาหน้าเว็บ (ทุกบล็อกที่ทำหน้า)

1. ใช้ `ctx.render(req, res, {title, body, script})` เสมอ · `body` ต้อง escape ค่าจาก DB ด้วย `ctx.esc`
2. **ข้อความใน element ที่มี `data-testid` = ค่าตรงตัวเท่านั้น** (ป้ายกำกับเช่น "ค่าธรรมเนียม:" อยู่นอก element) เช่น `<p>ค่าธรรมเนียม <strong data-testid="fee-total">฿1,010</strong></p>`
3. element ที่ "แสดงเมื่อ…/ไม่ render เมื่อ…" → **ไม่อยู่ใน DOM** เมื่อไม่เข้าเงื่อนไข (ห้ามซ่อนด้วย `hidden`/CSS) · ปุ่ม "ใช้ไม่ได้" → อยู่ใน DOM พร้อม `disabled`
4. รายการซ้ำใช้ testid ซ้ำได้ แต่ **ห้ามใช้ `id` ซ้ำ** · ช่องกรอกทุกช่องมี `<label for>` หรือ `aria-label` · ปุ่มทุกปุ่มมีข้อความ
5. ตารางห่อด้วย `<div class="table-wrap" tabindex="0" role="region" aria-label="…">` · หัวตาราง `<th scope="col">` มีข้อความทุกช่อง
6. ปุ่มที่เรียก API: ใช้ `App.api()` → สำเร็จ = `location.reload()` (หรืออัปเดตหน้าตามที่สเปกระบุ) · ไม่สำเร็จ = `App.showError(data.message)` (เว้นแต่สเปกระบุ testid error เฉพาะช่อง) · ห้าม `alert()`/`confirm()` ของเบราว์เซอร์
7. สถานะ/ระดับใช้ `ctx.views.statusBadge` / `levelBadge` เสมอ (มีข้อความ + สี)
8. ห้ามใส่เลขบัตร 13 หลัก/เบอร์โทรเต็มใน HTML ของจอเจ้าหน้าที่/ผู้บริหาร (ยกเว้นหลัง unmask ที่ JS ใส่เอง)

ตัวช่วยฝั่ง client ที่ layout (B01) ใส่ให้ทุกหน้า (`window.App`):

| ฟังก์ชัน | ทำอะไร |

| `App.api(method, url, body?)` | `fetch` แบบ same-origin · `body` เป็น object → JSON · เป็น `FormData` → multipart · คืน `Promise<{ok, status, data}>` (`data` = JSON ที่ parse แล้ว หรือ `null`) |

```sql
);

);
```
